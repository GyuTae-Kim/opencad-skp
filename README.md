# OpenCAD SketchUp 뷰어

SketchUp(.skp) 파일을 설치 없이 브라우저에서 3D로 여는 뷰어 앱과, 그 안에서 쓰는 SketchUp 해석기입니다.
파일은 서버로 보내지 않고 브라우저 안(웹 워커)에서 읽고, 결과 장면(`Scene3d`)은 [opencad-viewer3d](https://github.com/GyuTae-Kim/opencad-viewer3d)로 그립니다.

- 앱 주소(배포 예정): https://gyutae-kim.github.io/opencad-skp/
- 함께 쓰는 저장소: [opencad-viewer3d](https://github.com/GyuTae-Kim/opencad-viewer3d)(3D 뷰어 코어) ·
  [opencad-nc](https://github.com/GyuTae-Kim/opencad-nc) · [opencad-step](https://github.com/GyuTae-Kim/opencad-step) ·
  [OpenCAD 도구 목록](https://gyutae-kim.github.io/opencad)

SketchUp 형식은 공개 명세가 없습니다. 처음에는 인터넷에 공개된 표본 파일의 바이트만 보고 구조를 추론했고(SketchUp SDK·다른 SKP 읽기 프로그램의 코드는 보지 않음),
2026-10에 비공개 참조 해석기(SketchUp C API를 비교 기준으로 맞춘 SKP 해석기)의 형식 지식과 비공개 참조 뷰어의 화면 규칙(단위 표기·부드러운 음영·치수선 그리기·장면 적용)을
옮겨 더했습니다(코드는 이 저장소 꼴로 새로 씀). SketchUp 7·8·2013~2020의 옛 형식(MFC 객체 직렬화)도 같은 때 참조 해석기의 legacy 해석 지식을 옮겨 읽습니다.
무늬(텍스처) 투영·색 바꾼 무늬 규칙도 같은 기록에서 옮겼습니다.
조사 기록과 출처는 [docs/formats/skp.md](docs/formats/skp.md)에 있습니다.

## 앱 사용법

1. **열기**: 위 막대의 "열기"를 누르거나, `.skp` 파일을 창 어디에나 끌어다 놓습니다. 휴대폰·태블릿(손가락 기기)은 파일 고르기 창에서 형식을 거르지 않습니다(iOS가 모르는 확장자를 흐리게 막지 않게 — 고른 뒤 해석기가 알립니다). "예제 열기"는 브라우저에서 만든 작은 집 모형(태그 넷·재질 11개·컴포넌트)을 엽니다.
   한 번에 파일 하나를 열고, 새 파일을 열면 바꿉니다(새 파일을 못 열면 보던 모형은 그대로 둡니다).
   - **최근 문서**: 고르거나 끌어다 놓아 연 파일은 이 브라우저의 IndexedDB(`opencad-skp`)에 새것부터 8개까지 저장합니다(60 MB 초과·예제는 저장하지 않음, 서버로 보내지 않음).
     휴대폰 브라우저가 뒤로 보낸 탭을 버렸다가 다시 읽어도 시작 화면의 최근 문서에서 바로 다시 엽니다. 줄마다 ✕로 지우고, "모두 지우기"로 목록을 비웁니다. 비공개 창처럼 저장소를 못 쓰면 카드가 나오지 않습니다.
     파일은 고른 그대로(File) 저장하므로 화면이 파일 바이트를 따로 읽어 들지 않습니다(그렇게 저장하지 못하는 브라우저면 바이트로 저장).
   - **큰 파일**: 파일을 통째로 읽지 않고 해석 워커에 그대로 넘깁니다. 2021 이후 파일은 워커가 꾸러미 목록과 필요한 항목만 읽고, 압축된 모형 데이터는 1 MiB씩 읽으며 풉니다(아래 "큰 모형 메모리").
2. **보기**: 왼쪽 끌기 돌리기 · 오른쪽(가운데) 끌기 옮기기 · 휠 확대. 휴대폰은 한 손가락 돌리기(10화소 넘게 움직일 때부터 — 그 안에서 떼면 누르기라 손가락이 조금 떨려도 고르기·측정 점 찍기가 됩니다), 두 손가락 옮기기·확대.
   보기 도구 막대에서 전체 보기, 표준 뷰, 이전·다음 보기(카메라 기록), 원근/평행, 음영·음영+모서리·무늬 없음·단색·숨은 선·와이어프레임·X-ray, 격자, 뷰 큐브, 좌표축, 파일 배경, 줄자, 각도기, 그림 저장, 단면, 보기 설정, 패널 열고 닫기를 고릅니다.
   "보기 설정"에는 외곽선(윤곽 굵게)·뒤 모서리·태그 색으로 칠하기·안내점·안내선 보이기와 그림자·안개·걷기·시야각·2점 투시, 전체 화면(Fullscreen API를 쓸 수 있는 브라우저만 — iPhone Safari에는 없음)이 있습니다.
   ? 키(또는 앱 설정 메뉴의 "키보드 바로 가기")로 바로 가기 안내를 엽니다(모달 — Esc·바깥 누르기로 닫으면 연 곳에 초점을 돌려줌).
   - **그림 저장**: 작은 창에서 크기(화면 크기, 기기 화소 비율이 2보다 낮으면 2배 크기 — 코어가 그릴 때 읽는 화소 비율을 잠깐 2로 둔다),
     배경 투명(배경만 검정·흰색으로 두 번 그려 차이 매트로 풂), 글·치수·측정 넣기(화면의 DOM 라벨·줄자 선과 글을 같은 자리·글꼴로 합침)를 고르고
     PNG 저장·공유(파일을 받는 Web Share 브라우저 — 휴대폰 공유 시트로 사진·메신저에)·인쇄(인쇄 전용 쪽에 그림 한 장과 이름·날짜)를 합니다.
   - **처음 보기**: 파일이 저장한 카메라가 모형을 실제로 보여 주면 그 카메라로 열고(아니면 전체 보기), 파일 스타일의 그리기 방식과 활성 모형 단면을 따릅니다.
     면 스타일은 SketchUp RenderMode 0 → 와이어프레임, 1 → 숨은 선(면을 배경 색으로 채워 뒤 모서리를 가림), 5 → 단색, 무늬를 끈 음영 → 무늬 없음, X-ray와 모서리 끔도 따르고,
     스타일의 윤곽선(굵기 포함, 큰 모형은 처음엔 끔)·뒤 모서리·태그 색으로 칠하기(태그 색, 장면 스타일이 바꿈)도 따릅니다. SketchUp 모서리는 따로 선분 묶음이라
     그물에는 코어 `triangleEdges: false`를 두어 숨은 선·와이어프레임에서 삼각형 대각선을 그리지 않고(와이어프레임도 SketchUp처럼 모서리만),
     모형 모서리 묶음에는 `hiddenEdges: true`를 두어 스타일 "뒤 모서리"(보기 설정의 "뒤 모서리" 토글)가 면 뒤의 모서리를 흐린 점선으로 그립니다
     (코어 0.8.0 `setRenderOptions({ hiddenEdges: { shaded: true, color } })` — SketchUp처럼 숨은 선뿐 아니라 음영 방식에서도, 점선 색은 지금 모형 모서리가 띠는 색).
   - **배경**: 3D 보기는 파일 스타일의 배경 색으로 그리고(장면을 고르면 그 장면 스타일의 색), 격자·뷰 큐브·덧그림 글은 배경 밝기에 맞는 색을 씁니다.
     "배경" 단추(휴대폰은 보기 설정의 "파일 배경 색")로 끄면 앱 테마 배경이고, 이 브라우저에 기억합니다.
     스타일의 하늘·지면(DrawHorizon·DrawGround)을 켠 파일은 코어 하늘·땅 기울기 바탕으로 그립니다: 하늘은 위가 하늘 색이고 지평선 쪽으로 밝아지며,
     땅은 지면 색(지평선 쪽은 하늘에 조금 섞임), 지평선은 카메라 앙각을 따라 움직입니다(장면 스타일이 켜고 끔을 알면 장면마다, 투명 배경 그림 저장에는 그리지 않음).
   - **모서리 색**: 모형 모서리는 파일 스타일의 모서리 색(SketchUp "모서리 색: 모두 같게" — ForegroundColor, 렌더링 7358 → style.xml 1014)으로 그리고,
     장면을 고르면 그 장면 스타일의 색으로 바꿉니다(스타일이 모르면 검정에 가까운 기본 색). 실제 파일 694개(2021+)는 모두 "모두 같게"였고 690개는 검정, 4개는 회색이었습니다.
     스타일이 "재질별"(모서리 재질, 없으면 감싼 그룹·컴포넌트 재질, 그것도 없으면 모서리 색)이나 "축별"(그리기 축과 나란한 모서리는 빨강·초록·파랑, 나머지는 모서리 색)이면
     모서리를 그 색으로 그리고, 장면을 고르면 그 장면 스타일을 따릅니다(EdgeColorMode — 렌더링 7348 → style.xml 1002, 2021+ 파일).
     꼬리표는 SketchUp에 딸린 파일 가운데 재질별인 표본 둘로 가렸고, 축별은 아직 표본이 없어 SketchUp 설명대로 그립니다([형식 문서](docs/formats/skp.md)).
   - **선 색**: 와이어프레임·숨은 선(면을 배경 색으로 채움)·X-ray에서는 선 뒤가 배경이라, 모서리·치수선·안내선 색이 그 배경(파일 하늘·지면을 쓰면 그 색도)과
     대비가 3:1(WCAG 그래픽 기준)보다 모자라면 코어 테마 선 색으로 그립니다(어두운 테마의 검은 모서리 → 밝은 선, 검은 배경 파일도 같음).
     음영·단색 방식, 밝은 테마의 기본 선 색(SketchUp처럼 검정), 흰 배경 파일, 단면 평면 표시·태그 색·고른 것 강조 색은 그대로이고,
     시스템 테마·그리기 방식·파일 배경·장면 배경·장면 스타일 모서리 색·문서가 바뀌면 다시 맞춥니다(`src/app/linecontrast.ts`).
     같은 규칙으로 구한 색을 코어 0.8.0 선 선택에도 넘깁니다(`edgeLooks`): 카메라를 보는 컴포넌트 윤곽선(`edgeColor` — 예전에는 와이어프레임·X-ray에서 재질 색이라
     어두운 테마에서 어두운 재질이면 묻혔음)·뒤 모서리 점선 색, 외곽선(모서리 색을 굵게 — 바탕과 3:1이 안 되면 읽히는 선 색).
   - **해·그림자·안개**: 파일(또는 그림자를 기억하는 장면)의 그림자 날짜·시각·위도·경도·시간대·북쪽으로 해 위치를 구하고(NOAA 식, 위치가 없으면 SketchUp 기본 볼더),
     그림자 보이기나 "해로 음영"을 켠 파일은 코어 해 조명(밝음·어둠 → 해 세기·주변광)과 그림자(깊이 그림 PCF)로 그립니다. "보기 설정"의 그림자로 켜고 끄며
     (설정이 없는 파일은 SketchUp 기본 11월 8일 13:30), 해가 지면 주변광만 씁니다. 땅 위 그림자(지면에 드리우기)는 그리지 않습니다.
     안개는 2021+ 렌더링 설정(DisplayFog·FogColor·FogUseBkColor·FogStartDist·FogEndDist — 735F~7363, 표준 파일과 실제 파일 값으로 맞춘 꼬리표)을 읽어 코어 선형 안개로 그리고,
     거리가 기본값(−1)이면 장면 범위로 정합니다. 정보 탭에 지금 해 고도·방위가 보입니다.
   - **장면 탭**: 장면(페이지)이 있는 파일은 3D 위에 장면 탭이 생깁니다. 누르거나 PageUp·PageDown으로 넘기면 장면이 기억하는 것만 바꿉니다
     (카메라는 장면 전환 시간 동안 부드럽게, 숨긴 태그, 숨긴 개체, 활성 단면, 스타일). 정보 탭의 장면 카드(파일 안 미리보기 그림)도 누르면 바뀝니다.
     장면 탭 앞의 ▶(재생)는 SketchUp 애니메이션처럼 지금 장면 다음부터 "장면 재생에 넣기" 장면(뺀 장면은 기울여 보임)을 전환 시간(4초에서 자름) + 지연 시간마다 넘기고,
     모형 설정이 되풀이를 끄면 한 바퀴에서 멈춥니다. 3D를 누르거나 굴리거나, 키를 누르거나, 장면을 직접 고르면 멈춥니다(■).
     모형에서 숨겼지만 숨긴 개체를 기억하는 장면이 숨기지 않는 인스턴스는 해석기가 그 노드 몫으로 보통 색 그림을 따로 두어(`meta.revealItems`, 범위·통계 밖)
     그 장면을 고르면 보이고, 그 노드를 숨기는 장면이면 다시 숨습니다(숨긴 형상 보기의 반투명 그림은 그동안 숨김).
   - **세로 화면의 장면**: 장면 카메라는 SketchUp처럼 세로 시야각을 지켜, 휴대폰 세로 화면에서는 장면의 가로(지붕·옆벽)가 잘렸습니다.
     세로 화면(종횡비 1 미만)에서는 처음 카메라와 장면 전환 때 장면이 만든 가로 범위(파일의 고정 종횡비, 없으면 16:10)를 지키게 시야각을 넓힙니다(90°까지, 평행 투영은 화면 높이).
     눈 자리는 그대로라 실내 장면도 벽을 지나가지 않습니다. 가로 화면·데스크톱은 그대로이고, 휴대폰을 돌리면 새 방향에 다시 맞춥니다.
     전체 보기·표준 뷰·뷰 큐브·맞춰 보기는 넓힌 시야각을 장면의 원래 시야각으로 되돌린 뒤 하고(가장자리가 늘어나지 않게),
     이전·다음 보기는 장면 맞춤으로 적은 칸을 지금 화면 방향의 시야각으로 되돌립니다(돌리기 전 넓은 시야각이 돌아오지 않음).
   - **걷기·시야각·2점 투시(카메라 띠)**: "보기 설정"의 걷기(1인칭)·2점 투시·"시야각·카메라 띠"로 3D 보기 아래에 카메라 띠를 엽니다(시야각 10~120° 슬라이더, 걷기·2점 투시 단추).
     걷기(SketchUp 걷기·둘러보기·카메라 위치 정하기, 코어 `setNavigation('walk')`)는 끌기 = 제자리에서 둘러보기, 휠·W/S·↑/↓ = 앞뒤, A/D = 옆, ←/→ = 돌기,
     Q/E·PageUp/PageDown = 위아래, Shift = 빠르게, 두 번 누르기 = 그 자리에 눈높이 5′6″(1.676 m)로 서기, Esc = 끝내기입니다.
     SketchUp 걷기처럼 중력(바닥·계단을 따라감 — 그동안 위아래 키는 듣지 않음)과 부딪힘(벽 앞에서 멈추고 벽을 따라 미끄러짐)을 처음부터 켜고(코어 0.8.0 `gravity`·`collide`),
     걷는 동안 카메라 띠의 "중력"·"부딪힘"으로 켜고 끕니다(발밑에 바닥이 없으면 그 높이 그대로). 걷는 동안 누르기는 고르지 않고
     (서기용 두 번 누르기가 그룹에 들어가지 않게), 패널 목록·메뉴·슬라이더에 초점이 있으면 화살표·PageUp·PageDown은 그쪽이 씁니다. 휴대폰은 왼쪽 아래 조이스틱으로 걷고
     (코어 `setWalkInput`), 한 손가락으로 둘러보고 두 손가락으로 벌려 앞으로·끌어 옆/위아래로 갑니다. 원근으로 바꾸고 측정을 켜면 걷기를 끝냅니다.
     2점 투시(SketchUp 카메라 › 2점 투시)는 눈 자리·방향을 두고 수평으로 본 뒤 렌즈를 위아래로 옮겨(코어 `shiftY`) 세로선을 곧게 하며, 돌려 앙각이 생기면 끝납니다.
     파일·장면의 2점 투시 카메라도 이렇게 열고, 위 벡터가 기운 카메라는 굴림(`roll`)으로 엽니다(90° 넘게 기운 깨진 값은 버림). 시야각을 바꾸면 렌즈 이동도 함께 맞춥니다.
   - **줄자(T)·각도기**: SketchUp처럼 끝점(초록)·중간점(청록)·모서리 위(빨강)·면 위(파랑)에 붙고, 시작점에서 축 방향(빨강 X·초록 Y·파랑 Z)으로 움직이면 축에 고정합니다.
     커서 둘레의 두 모서리가 3D에서 만나는 곳에는 교차점(빨강 ×)으로 붙습니다 — 다른 그룹의 모서리끼리, 보조선과 모서리처럼 SketchUp이 나누지 않은 교차이고,
     화면에서만 엇갈리는(깊이가 다른) 모서리나 끝에서 만나는 꺾인 곳(끝점이 맡음)은 아닙니다(코어 0.9.0 `segmentIntersection`, 허용치는 그 자리 반 화소).
     호·원의 중심(초록 원과 십자 — 곡선을 한 번 훑고 가운데로 가면 붙음, 최근 넷까지 기억)과, 시작점에서 모서리·면에 내린 수직 발(자홍 ㄴ — "모서리에 수직"·"면에 수직",
     맞은편 벽까지의 거리)에도 붙습니다. 최근 결과 10개는 패널 아래 띠의 "최근 측정"(휴대폰은 측정 띠의 목록 단추)에 남고, 줄마다·모두 복사합니다.
     - **모서리와 나란히**: 커서로 모서리를 한 번 지나간 뒤 시작점에서 그 모서리와 나란한 쪽(화면 각 6° 안)으로 가면 그 방향 선에 붙습니다(SketchUp 관례대로 자홍 —
       고무줄 선과 기준 모서리 점선이 자홍). 축과 함께 맞으면 화면에서 선에 가까운 쪽(같으면 축), 축과 나란한 모서리는 축에 맡깁니다. 끝점·모서리 같은 점 추정이 먼저입니다.
     - **모서리에 수직**: 같은 자리에서, 지나간 모서리에 수직인 쪽(화면 각 6° 안)으로 가면 시작점을 지나 그 방향 선에 붙습니다(자홍 고무줄 선과 기준 모서리 점선,
       툴팁 "모서리에 수직"). 모서리에 수직인 방향은 평면 하나를 이루므로 쓸 만한 방향만 봅니다: 시작점에서 그 모서리 직선으로 내린 수직과, 그리기 축을 그 평면에 비친 방향
       (평면도에서 기운 벽에 수평으로 수직, 기운 서까래에는 그 세로 평면 안에서 수직)입니다. 커서가 면 위에 있고 지나간 모서리가 그 면 위(또는 면과 나란함)면
       그 면 안에서 모서리에 수직인 방향도 봅니다(기운 지붕 면에서 처마를 지나간 뒤 비탈을 따라 오르는 쪽 — 처마 위에서 시작하면 내린 수직이 없고 축을 비친 방향은 수평·수직뿐입니다).
       축과 겹치는 방향은 축이 맡고, 여럿 맞으면 화면에서 선에 가까운 쪽
       (같으면 축 → 나란히 → 수직)입니다. 시작점에서 모서리에 내린 수직 발(점 추정)이 먼저입니다.
     - **방향 잠금**(SketchUp 공개 도움말의 추론 잠금): 줄자 끝점·각도기 방향을 잡는 동안 Shift를 누르고 있으면 지금 방향 추론(빨강·녹색·파랑 축, 모서리와 나란히·수직,
       시작점에서 내린 수직)을 잠그고, 떼면 풉니다. 모서리 끝에서 시작해 그 모서리를 따라 가리키면 표식은 "모서리에"(점 추정이 먼저)지만
       Shift는 그 모서리 방향을 잠급니다(축과 나란한 모서리면 그 축 — 벽 모서리 끝에서 높이를 잴 때). →·←·↑는 빨강·녹색·파랑 축, ↓는 모서리와 나란히·수직(커서 밑 것, 없으면 앞서 지나간 모서리와 나란히)을 잠그고
       같은 키를 다시 누르면 풉니다. 잠근 동안은 커서를 어디에 두든 시작점을 지나는 그 선 위에 찍고(굵은 실선, 표식에 고리, 툴팁에 "잠금"),
       끝점·중간점·중심·교차점을 가리키면 그 점을 선에 수직으로 내린 자리를 찍습니다 — 예: 파랑 축을 잠그고 지붕 끝점을 가리키면 그 높이까지의 길이.
       그런 점이 없는 모서리·안내선을 가리키면 잠근 선이 그 모서리와 만나는 자리에(툴팁 "파랑 축에 · 모서리에 · 잠금", 모서리 위처럼 빨강 사각형에 고리),
       면을 가리키면 잠근 선이 그 면을 뚫는 자리에 붙습니다(툴팁 "파랑 축에 · 면에 · 잠금", 파랑 마름모에 고리 — 같은 도움말의 "추론을 잠근 채 다른 형상을 가리켜 참고하기",
       예: 창 끝점에서 파랑 축을 잠그고 박공 비낀 모서리나 지붕 면을 가리키면 그 높이까지의 길이). 잠근 선은 축·나란함·수직 어느 것이든 되고,
       잠그기 전 축이 모서리·면과 만나는 점을 보고 Shift를 눌러도 점이 그 자리에 남습니다. 면은 아래 "축이 모서리·면과 만나는 점"처럼 그 자리에서 다시 맞춰 봅니다.
       점을 찍거나 Esc로 취소하면 풀립니다. 각도기 중심을 찍기 전에는 →·←·↑가 각도기 평면을 그 축에 고정합니다(빨강·녹색·파랑 각도기, 다시 누르거나 Esc로 풂).
       휴대폰·터치는 측정 띠의 잠금 단추로 잠급니다(아래 측정 띠).
     - **다른 점에서 끌어온 축**(SketchUp 공개 도움말 "Introducing Drawing Basics and Concepts"의 점에서 추론): 끝점·중간점·중심·교차점·수직 발·안내점 위에
       커서를 0.5초 가만히 두면(2화소 안) 그 점을 끌어옵니다(작은 +, 최근 셋까지 — 상태 줄에 "끌어온 점 1개"). 그 뒤 면 위·빈 곳을 가리키면 그 점에서 빨강·녹색·파랑 축 방향 선 위에 붙고
       (툴팁 "끌어온 점의 빨강 축에", 그 점에서 커서까지 축 색 점선), 시작점을 찍은 뒤에는 시작점 축 위에서 끌어온 점과 줄 맞춘 자리에 먼저 붙습니다
       (툴팁 "파랑 축에 · 끌어온 점과 줄 맞춤" — 예: 지붕 끝점을 끌어온 채 땅의 한 점에서 파랑 축을 따라 올라가면 그 높이에서 멈춤).
       두 점을 끌어왔으면 두 점의 서로 다른 축이 만나는 자리에도 붙고(툴팁 "끌어온 빨강 축과 파랑 축의 교차점", 교차점처럼 빨강 ×와 두 점에서 각 축 색 점선 —
       예: 벽 밑 끝점의 빨강 축과 창 끝점의 파랑 축이 만나는 창 아래 바닥 자리), 끌어온 축이 모서리·안내선을 지나는 자리에도 붙습니다
       (툴팁 "끌어온 점의 빨강 축에 · 모서리에", 모서리 위처럼 빨강 사각형). 높이가 달라 화면에서만 엇갈리는 축은 만나지 않습니다.
       줄 맞춘 자리와 이 두 자리는 두 선이 만나는 한 점이라 모서리 위보다 먼저이고(모서리를 따라가다 끌어온 점과 줄이 맞으면 멈춤), 여럿이면 화면에서 가까운 쪽입니다.
       시작점 축 위의 자리(줄 맞춘 자리, 시작점도 지나는 끌어온 축 위의 교차)는 Shift로 그 축을 잠글 수 있고, 모서리를 지나는 자리는 그 모서리가 시작점을 지나면 그 모서리 방향을 잠급니다.
       끌어온 점의 축만으로는 시작점을 지나지 않아 잠그지 않습니다. 끝점 같은 점 추정이 먼저이고, 그리기 축을 옮긴 모형은 그 축으로 끌어옵니다.
       방금 누른 점과 진행 중 측정의 시작점은 머물러도 끌어오지 않습니다. 측정을 마치거나 다시 재기·Esc(끌어온 점만 있을 때도)·도구 바꾸기면 잊고,
       안내가 아니라서 되돌리기·파일별 안내 기억에 들지 않습니다. 휴대폰·터치는 탭에 머무를 커서가 없어 정밀 조준으로 끌어옵니다(아래 정밀 조준).
     - **축이 모서리·면과 만나는 점**(같은 도움말의 추론 합치기 — 축 위(On Axis)에 모서리 위(On Edge)·면 위(On Face)를 겹친 점): 시작점을 찍은 뒤
       빨강·녹색·파랑 축을 따라가다 그 축이 모서리·안내선을 지나는 자리에 붙고(툴팁 "빨강 축에 · 모서리에", 모서리 위처럼 빨강 사각형과 축 색 고무줄),
       커서 밑 면을 뚫는 자리에도 붙습니다(툴팁 "파랑 축에 · 면에", 면 위처럼 파랑 마름모 — 예: 벽 모서리 밑 끝점에서 파랑 축을 따라 올라가 처마 위 비탈진 지붕 면에 닿는 높이).
       끌어온 점의 축이 면을 뚫는 자리에도 붙습니다(툴팁 "끌어온 점의 파랑 축에 · 면에", 시작점을 찍기 전에도). 두 선(선과 면)이 만나는 한 점이라 모서리 위·축 고정보다 먼저이고,
       끌어온 점 후보와 같은 점이면 끌어온 점 후보가 남습니다. 시작점 축 위 점이라 Shift로 그 축을 잠급니다.
       면은 그 자리에서 면만 다시 맞춰 보므로(숨긴 항목·단면에서 잘린 쪽은 빼고) 앞에 다른 면이 가리면 붙지 않고, 면 위에 그린 모서리나 면 앞을 지나는 선은 면을 가리지 않습니다.
       상자 모서리처럼 축과 수직인 모서리나 축과 수직인 면에서는 시작점에서 내린 수직 발("모서리에 수직"·"면에 수직")이 같은 자리라 그쪽이 먼저입니다.
     - **측정값 칸(VCB)**: 줄자를 켜면 3D 보기 오른쪽 아래에 "길이" 칸이 생겨 지금 길이(시작점 → 커서, 다 재면 그 거리)를 보입니다(각도기는 "각도" 칸).
       SketchUp 줄자처럼 시작점을 찍고 커서를 잴 방향(끝점·모서리·축 고정)에 둔 채 숫자를 치면 이 칸에 들어가고(그동안 1~7 보기 키는 칸이 받음),
       Enter로 시작점에서 그 길이만큼 간 자리에 안내점(✕)을 찍고 결과를 시작점 → 안내점으로 바꿉니다. 두 점을 다 잰 뒤 칸에 길이를 넣으면
       그 결과의 방향으로 찍습니다 — 휴대폰은 커서가 없어 이쪽이며, 결과가 나오면 측정 띠 둘째 줄에 칸이 생기고 누르면 숫자 자판이 뜹니다
       (건축·분수 인치 모형은 ' " / 가 있는 글 자판). 글은 모형 단위로 읽고 단위를 붙여도 됩니다(1200 · 1.2 m · 120 cm · 5'6" · 6 1/2" · 앞의 −는 반대쪽).
       쉼표는 화면 언어를 따릅니다: 독일어는 소수 쉼표(1,5 = 1.5), 그 밖의 언어는 세 자리 묶음이면 천 단위 구분(1,500 = 1500)이고 아니면 소수 쉼표로 읽습니다.
       시작점이 모서리 위(끝점·중간점이 아닌 곳)면 SketchUp 줄자처럼 안내점 대신 그 모서리와 나란한 안내선(화면 끝까지 뻗은 점선)을
       커서 쪽으로 친 거리만큼 띄워 둡니다(거리는 모서리에 수직으로 잼, 다 잰 뒤면 결과 쪽으로). 누르기로 재는 두 점 거리는 그대로입니다.
       이 뷰어는 모형을 고치지 않으므로 SketchUp에서 길이를 쳐 모형 크기를 바꾸는 쓰임은 옮기지 않고 안내점·안내선만 둡니다:
       "벽 모서리에서 900 mm 떨어진 곳이 어디인지"를 보고 그 자리에서 다시 잴 수 있게(안내점은 끝점처럼, 안내선은 모서리 위처럼 붙고 안내선이 모서리·다른 안내선과
       만나는 곳은 교차점, 모형·파일에 넣지 않는 보기 전용 표시, 저마다 50개까지, 같은 자리·같은 직선에는 겹쳐 두지 않음, 칸의 ✕로 모두 지움, 파일별로 이 브라우저에 기억 — 아래 안내 기억).
       칸 안의 Esc는 입력만 그만둡니다.
     - **안내 두기**: SketchUp 줄자·각도기는 누르기로도 안내를 둡니다(커서 옆 +). 이 뷰어는 재기만이 기본이고, Ctrl(Mac은 Option)만 눌렀다 떼면 안내 두기를
       켜고 끕니다(그사이 다른 키·누르기·휠이 있으면 그대로 — 휴대폰은 측정 띠의 안내 두기 단추). 켜면 커서 옆에 +가 보이고, 줄자 둘째 누르기가 안내를 둡니다:
       모서리 위에서 시작했으면 둘째 점을 지나 그 모서리와 나란한 안내선(결과는 모서리와 안내선 사이, 모서리에 수직인 거리 — 둘째 점이 모서리 직선 위면 재기만),
       끝점·꼭짓점 같은 점에서 시작했으면 둘째 점에 안내점입니다. 각도기는 셋째 누르기가 중심을 지나 잰 방향으로 안내선을 둡니다. 둘 안내선은 옅은 점선으로 미리 보입니다.
       기본을 재기만으로 둔 까닭: 이 뷰어는 모형을 고치지 않고 재기가 주된 쓰임이라, 잴 때마다 안내가 쌓이면 화면이 어지럽고 안내가 다음 측정의 추정 후보(끝점·모서리처럼 붙음)로
       끼어들며, 지금까지 두 점을 누르면 재기만 하던 사용법·최근 측정 기록도 그대로 두기 위해서입니다.
     - **안내 고르기·지우기**: 줄자·각도기에서 안내점·안내선 위를 누르면(측정 점도 그대로 찍힘) 그 안내를 고릅니다(파랑, 굵게). 칸으로·안내 두기로 방금 둔 안내도 골라 두어
       잘못 두었으면 바로 지울 수 있습니다. 다른 곳·빈 곳을 누르거나 Esc·다시 재기면 풉니다(Esc 차례는 그대로).
       Delete·Backspace, 또는 측정값 칸에 생기는 휴지통 단추(휴대폰은 측정 띠 둘째 줄)로 고른 안내 하나만 지웁니다. 지우려고 누른 안내가 시작점도 찍었으면 그 점도 거둡니다.
     - **안내 되돌리기·다시 하기**: 이 뷰어가 바꾸는 것은 안내점·안내선뿐이라, 안내를 두기(칸으로·안내 두기·모서리 두 번 누르기)와 지우기(하나·모두)를
       하나씩 되돌리기 목록에 쌓습니다(100단계까지, 넘으면 오래된 것부터 버림). Ctrl+Z(Mac은 ⌘Z)로 되돌리고 Ctrl+Y·Ctrl+Shift+Z(⌘⇧Z)로 다시 합니다.
       줄자·각도기를 끈 동안에도 되고, 측정값 칸·찾기 칸처럼 글을 넣는 곳에서는 브라우저의 글 되돌리기입니다. 되돌리는 것은 안내뿐이라 측정 결과·최근 측정·진행 중 점은 그대로 둡니다.
       되돌린 안내를 골라 두었으면 고른 것을 풀고, 되돌린 뒤 안내를 새로 바꾸면 다시 하기 목록은 비웁니다. 파일을 열 때마다 목록을 비웁니다(안내는 아래 안내 기억대로 되살림).
       휴대폰·터치는 측정 띠 둘째 줄의 되돌리기 단추(반시계 화살표, 되돌릴 것이 있을 때만)로 하나씩 되돌리고,
       그 바로 옆 다시 하기 단추(시계 방향 화살표, 다시 할 것이 있을 때만)로 되돌린 것을 하나씩 다시 합니다.
     - **안내 보이기**: 둔 안내점·안내선은 줄자·각도기를 끈 뒤에도 그대로 보입니다(SketchUp처럼 — 카메라를 옮기면 따라감). 고르기·지우기는 줄자·각도기를 켠 동안만 합니다.
       "보기 설정"의 "안내점·안내선 보이기"(기본 켬, 이 브라우저에 기억)를 끄면 안내를 그리지 않고, 추정에도 붙지 않고, 누르기로 고르지도 않습니다(파일의 보조선은 패널의 보조선 보기로 따로).
       숨긴 채 안내를 두거나 되돌리면 무엇이 바뀌었는지 보이게 다시 켭니다.
     - **안내 기억(파일별)**: 둔 안내점·안내선은 바뀔 때마다(두기·지우기·되돌리기) 그 파일 내용의 지문(SHA-256)을 열쇠로 이 브라우저에 기억해,
       새로 고치거나 다른 파일을 열었다가 같은 파일(이름이 달라도 내용이 같으면)을 다시 열면 그대로 되살아납니다. 파일 이름·경로는 기억하지 않고 지문만 둡니다.
       지문은 해석 워커가 모형을 보낸 뒤 파일을 4 MiB씩 읽으며 구합니다(8 MiB 이하는 브라우저 내장 SHA-256으로 한 번에). 파일 전체 바이트로 구한 값과 같아서 2026-10-28 판에서 기억한 안내도 그대로 되살아납니다.
       파일 40개까지 기억하고, 넘거나 저장 글이 40만 글자를 넘으면 오래 쓰지 않은 파일부터 버립니다. 저장이 막힌 브라우저(사생활 보호 창 등)에서는 기억만 하지 않고 그대로 씁니다.
       되돌리기 목록은 기억하지 않아, 되살린 안내가 처음 상태입니다(새로 고친 뒤 Ctrl+Z로 그 전 안내로 가지 않음).
       "보기 설정"의 "이 파일의 안내 모두 지우기"(안내가 있을 때만, 줄자·각도기를 끈 동안에도)는 이 파일의 안내를 모두 지우고 기억도 지웁니다.
       측정값 칸의 ✕처럼 되돌리기 한 칸으로 쌓여 Ctrl+Z·되돌리기 단추로 되살리면 다시 기억합니다.
     - **모서리 두 번 누르기**: SketchUp 줄자처럼 모서리 위를 두 번 누르면(휴대폰은 두 번 탭) 그 모서리를 지나는 끝없는 안내선을 둡니다(안내 두기를 켜지 않아도).
       곡선(원·호)은 누른 조각 하나의 직선을 따릅니다. 두 번 누르기는 코어와 같은 문턱(0.45초 안, 마우스 6화소·손가락 24화소 안)으로 알아보고,
       첫 누르기가 찍은 시작점은 거두고 그 누르기가 지운 결과는 되돌립니다(시작점을 찍은 뒤 두 번 눌렀으면 첫 누르기로 마친 측정은 남습니다).
       둔 안내선은 골라 두어 Delete·휴지통 단추로 바로 지울 수 있고, 같은 직선에 이미 안내선이 있으면 그것을 고릅니다(안내선 50개 한도는 같음).
       끝점·교차점처럼 모서리가 여럿 만나는 곳은 두 번 눌러도 재기만 하고, 각도기는 두 번 누르기로 안내선을 두지 않습니다.
     각도기는 중심 → 기준 방향 → 잴 방향을 누르고, 평면은 커서 밑 면(없으면 화면을 가장 정면으로 보는 축 평면), Shift로 평면을 고정합니다. 값은 모형 단위 형식(십진·건축·분수·공학, 정밀도, 반올림이면 ~)으로 보입니다.
     중심과 기준 방향을 찍은 뒤 각도를 치면(도 34.1, 경사 높이:밑변 1:6, 앞의 −는 반대쪽) 중심을 지나 기준 방향에서 그만큼 커서 쪽으로 돈 안내선을 둡니다
     (다 잰 뒤면 결과의 잰 방향 쪽으로 — 휴대폰은 결과가 나오면 측정 띠의 "각도" 칸을 누름). 쉼표 규칙과 숫자 자판은 길이와 같습니다.
     줄자·각도기는 파일을 열 때 함께 받아 두므로 보통 바로 켜집니다. 아직 받는 중에 누르면 단추가 눌린 채 상태 줄에 "측정 도구를 받는 중…"을 보이다가 받으면 켜고,
     그사이 다른 도구를 누르면 마지막으로 누른 도구를 켭니다. 같은 단추를 다시 누르거나 Esc를 누르면 켜지 않습니다.
     받지 못하면 알림을 보입니다. 인터넷이 끊겼으면 연결된 뒤 단추를 다시 누르면 다시 받고, 앱의 새 버전이 나와 예전 조각이 없으면 새로 고친 뒤 최근 문서에서 다시 엽니다.
   - **문자·치수**: 파일의 글(지시선 글·화면 고정 글)과 치수(선형·반지름·지름)를 3D 위 라벨로 그립니다. 치수선·연장선·지시선, 보조선(점선), 단면 기호는 선으로 그리고, 태그·숨김을 따릅니다. 겹치는 라벨은 뒤의 것을 숨깁니다.
     치수·지시선의 끝 표시(닫힌·열린 화살, 빗금, 점)와 연장선이 치수선 너머로 조금 나간 곳은 SketchUp처럼 화면 크기(9화소, 넘침은 그 0.6배 —
     화면에서 짧게 보이는 치수는 선 길이의 0.15배로 줄임)로 덧그림 층에 매 화면 그려, 확대·축소해도 너무 크거나 작아지지 않습니다(예전에는 장면 크기에 맞춘 선분).
     그 선이 숨으면(태그·주석 켜고 끄기·숨김·숨긴 그룹·단면에 잘린 쪽) 함께 숨고, 선 색 대비로 바꾼 색을 따르며, 형상에 가린 표시는 라벨처럼 카메라가 멈추면 숨깁니다.
     그림 저장에도 같은 크기로 들어갑니다("글·치수·측정 넣기"를 꺼도 — 치수선은 3D 그림에 있으므로).
     형상 뒤의 라벨도 숨깁니다: 카메라가 0.16초 멈추면 라벨 기준점(지시선 글은 붙는 점, 치수·지시선 없는 글은 글 자리)의 화면 자리에서 코어 고르기로 앞을 가린 불투명 면이 있는지 봅니다
     (음영 방식만 — X-ray·와이어프레임은 가리지 않음, 반투명 면·단면에 잘린 쪽·숨긴 항목은 가리지 않음, 화면 고정 글은 늘 보임, 한 번에 2,000개까지).
   - **단면**: 끔·X·Y·Z로 축에 수직인 평면을 두고, 슬라이더로 위치(장면 범위 안)를, 뒤집기로 잘라 낼 쪽을 바꿉니다. 새 파일을 열면 꺼집니다.
     해석기가 정의마다 닫힌 껍질(면 고리가 쓰는 모서리마다 쓰임이 꼭 둘, 숨긴 면·삼각화 못 한 면 없음)인지 가려, 닫힌 입체 배치만 따로 모은 그물에
     채우기 묶음(코어 `capGroup`, 칸마다 하나 — 범위 상자가 겹치거나 안에 든 입체는 그 칸의 다른 묶음, 4개까지)을 줍니다(코어는 묶음 안을 홀짝으로 채워 겹친 곳이 비므로). 단면에서 그 입체의 잘린 면을 채우고(SketchUp 2018+ 스타일 "단면 채우기"를 따르며 없으면 2018 이상만 채움),
     "채우기" 단추(휴대폰은 단면 메뉴)로 켜고 끕니다. 열린 면·얇은 판·반투명 재질이 든 입체는 테두리만 그립니다.
     같은 칸 안에서 서로 겹친 입체는 겹친 곳이 비어 보일 수 있습니다(홀짝 채우기). 엔티티 정보는 SketchUp 입체(방향이 맞고 떠 있는 모서리·안쪽 그룹 없음)를
     "입체 그룹·입체 컴포넌트"로 부르고 부피를 보입니다.
     파일 단면(처음 열 때 활성 단면, 장면이 기억하는 단면, 태그·재질 탭의 단면 평면 목록)은 여러 개를 함께 씁니다(코어 `setSections`, 한 번에 6개):
     모형 단면은 모형 전체를, 그룹·컴포넌트 안 단면은 그 그룹 안쪽만 자르고(해석기가 단면이 든 노드를 따로 나눠 항목을 안다), 같은 그룹의 단면은 하나만 켭니다.
     그 그룹만 자를 수 없는 단면(그룹이 너무 많아 나누지 않음)·한도를 넘은 단면은 목록 아래에 수를 알립니다. 글·치수 라벨과 측정 추정도 모든 단면을 따릅니다.
   - 창이 좁아지면 아이콘으로 알 수 있는 단추부터 글을 숨기고(제목 풍선은 남음), 태블릿 폭에서는 줄을 바꿉니다.
   - **휴대폰(폭 760px 미만이거나 손가락 기기에 높이 500px 미만인 가로 화면)**: 보기·치수 확인에 쓰는 단추만 한 줄에 둡니다(전체 보기·표준 뷰·줄자·각도기·단면·보기 설정·패널).
     뷰 큐브를 작게, 패널은 처음엔 닫아 둡니다. 손가락 기기에서는 제목 막대 단추를 폭 40px 이상, 장면 탭을 높이 38px로 키웁니다(폭 400px 이하에서는 제목을 "OpenCAD"만).
     단면은 메뉴에서 축을 고르면 그때만 위치 슬라이더·뒤집기 줄이 생기고, 이전·다음 보기·투영·그리기 방식·격자·뷰 큐브·좌표축·파일 배경 색·그림 저장은 "보기 설정" 메뉴에 있습니다.
   - **측정 띠(휴대폰·터치)**: 줄자·각도기를 켜면 3D 보기 아래에 다음에 누를 곳 안내, 결과(거리와 dx·dy·dz, 각도)와 "다시 재기"·끝내기 단추가 뜹니다(Esc 대신).
     "다시 재기"는 찍은 점·결과 없이 끌어온 점만 남았을 때도 켜져 끌어온 점을 지웁니다.
     줄자 끝점·각도기 방향을 잡는 동안은 복사 단추 자리에 잠금 단추(자물쇠)가 있습니다. 정밀 조준으로 십자선을 축·나란한 방향(시작점을 지나는 모서리 위도)에 맞춘 채 다른 손가락으로 누르면
     그 방향을 잠그고(띠에 "빨강 축으로 잠금" 같은 글), 다시 누르면 풉니다. 잠근 채 떼거나 다른 곳을 누르면 그 선 위에 찍힙니다
     (잠근 채 십자선을 모서리·면 위로 옮기면 잠근 선이 그 모서리와 만나는 자리·그 면을 뚫는 자리).
     맞춘 방향이 없을 때 누르면(한 손으로 시작점을 탭한 바로 뒤 등) 띠 위에 잠글 방향 고르기 줄이 떠, 엄지로 "빨강 축으로 잠금"·"녹색 축으로 잠금"·"파랑 축으로 잠금"
     (시작점이 모서리 위였거나 지나간 모서리가 있으면 "모서리와 나란히 잠금"도) 가운데 하나를 누르면 그 방향을 잠급니다. 그대로 탭하거나 길게 눌러 조준하면 잠근 선 위에 찍히므로
     한 손으로 시작점 → 잠금 → 방향 → 끝점을 잽니다(SketchUp for iPad 줄자의 Lock X·Y·Z·Lock Parallel 도구 모드처럼 재기 전에 고름). 줄은 단추를 다시 누르거나,
     점을 찍거나 다시 재기·도구 끄기를 하면 닫힙니다(손가락을 뗀 뒤 누르면 예전처럼 방향을 잡는 동안 마지막으로 본 방향을 잠급니다).
     맨 앞의 안내 두기 단추(점선과 +)는 누르기로 안내를 둘지 켜고 끕니다(켜면 강조, 잠깐 알림). 안내가 있으면 둘째 줄의 측정값 칸 옆에 안내 수(누르면 모두 지움)와,
     고른 안내가 있을 때만 휴지통 단추가 생겨 그 하나를 지웁니다. 되돌릴 안내 바꿈(두기·지우기)이 있으면 그 줄에 되돌리기 단추(38px)가 생겨 하나씩 되돌립니다(모두 지운 뒤에도 남아 되살림, 다 되돌리면 사라짐).
     되돌린 것이 있으면 그 옆에 다시 하기 단추(38px)가 생겨 하나씩 다시 하고, 안내를 새로 바꾸거나 다 다시 하면 사라집니다.

     (기준점 둘레 네 귀 → 결과 선을 따라 → 가린 것 바로 위·아래, 측정 점 표식도 될 수 있으면 비킴). 가리지 않으면 예전처럼 결과 선 가운데이고,

## 라이브러리로 쓰기

```ts
import { skpToScene } from 'opencad-skp';

const scene = skpToScene(bytes, { name: 'model.skp' });
// scene: Scene3d (opencad-viewer3d의 Viewer3d.setScene에 넘긴다), scene.warnings에 읽지 못한 것
```

선택:

- `outline: true` — 그룹·컴포넌트를 하나씩 고르게 나눕니다. 기본은 꺼져 있어 예전처럼 (태그, 재질)마다 하나로 모읍니다.
  - `meta.outline`: 모형 바로 아래 항목 목록(이름·종류·정의·태그·면 수·안쪽까지의 항목 id·나무 노드). 윗단계 인스턴스가 1,000개를 넘으면 나누지 않고 `meta.outlineSkipped`에 수를 적습니다.
  - `meta.tree`: 여러 단계 나무(`SkpTree`, 형식 배열). 넓이 우선으로 노드 5만 개까지(단계 단위로 자르고 `TREE_MORE` 표시).
    그리기 호출이 터지지 않게, 그물·모서리 항목 수 어림이 3,000 안인 가장 깊은 단계(`splitDepth`)까지만 노드마다 따로 모으고,
    더 깊은 노드는 그 단계 조상의 그물에 함께 넣습니다. 펼치기는 깊이 우선이라 노드 안쪽이 각 그물 안에서 이어진 구간이 되므로,
    구간 목록(`runItem`·`runStart`·`runNode`, 노드마다 `runFirst`·`runEnd`)으로 고른 삼각형의 가장 안쪽 노드를 찾고 깊은 노드도 강조·맞춰 보기할 수 있습니다.
- `extras: true` — 부드러운·매끈한 모서리(`skp-soft-*`)와 숨긴 형상(숨긴 면·모서리·인스턴스, `skp-hidden-*`)을 따로 묶어 더 넣고 `meta.extraItems`에 id·수를 적습니다(범위·통계에는 넣지 않음).
- `smooth: true` — 매끈한 모서리(깃발 0x10)로 이어진 면의 꼭짓점 법선을 평균해 `Mesh3d.normals`로 냅니다(둥근 곡면 음영, 크게 접힌 곳은 평균하지 않음). 기본 꺼짐(예전과 같은 평면 음영).
- `meta.faceRuns`(그물마다 면 경계 — 면 k의 삼각형은 `[runs[k], runs[k + 1])`)·`meta.segmentCurves`(모서리 묶음마다 선분의 놓인 곡선 번호, -1 = 곡선 아님):
  고른 삼각형·선분에서 SketchUp 면 하나·곡선 하나를 찾습니다(화면의 면 넓이·곡선 길이). 해석기가 면마다 삼각형을 이어 붙이므로 출력 형상은 그대로입니다.
- `annotations`(기본 켬) — 문자·치수·보조선·단면을 펼쳐 선분 묶음(`skp-dims-*`·`skp-leaders-*`·`skp-guides-*`·`skp-sections-*`, 보조점은 `scene.points`)과 `meta.texts`·`meta.dimensions`·`meta.sectionPlanes`로 냅니다(범위에는 넣지 않음). 주석이 없는 모형은 출력이 예전과 같습니다.
- `onProgress(fraction, stage)` — 진행률(단계 안에서도 몇천 항목·몇 MB마다)을 알립니다(워커에서 진행 막대용).
- `skpToSceneAsync(bytes, opts)` — `skpToScene`과 같은 장면을 내되, 압축된 `model.dat`가 `streamMin`(기본 `STREAM_MIN_BYTES` = 1 MiB) 이상인 2021+ 파일은
  브라우저 내장 `DecompressionStream('deflate-raw')`로 조각조각 풀면서 읽습니다(풀린 `model.dat` 전체를 들지 않음 — 직접 쓴 풀기보다 몇 배 빠름).
  내장 풀기가 없거나 실패하면 `skpToScene`처럼 직접 풀고, 뿌리·정의 목록의 꼬리표 길이가 깨진 꼴은 통째로 풀어 예전처럼 앞부분을 살립니다(같은 결과).
  앱 워커는 아래 `skpFileToScene`으로 같은 길을 씁니다. `onModelRead`는 어떻게 읽었는지(`stream`·`held` — 재질·글꼴 절이 정의 절보다 뒤에 오거나 없어 정의 절을 통째로 든 것 ·
  `whole` · `shape` · `inflate`)를 알립니다.
- `inflated` — 미리 푼 꾸러미 항목(`Map<'model.dat', Uint8Array>`). 길이가 ZIP 목록의 원래 크기와 같을 때만 쓰고 아니면 직접 풉니다.
  해석기는 꺼내 쓴 항목을 이 Map에서 지웁니다(모형 요소를 다 읽으면 풀린 바이트가 놓이게).
- `releaseBytes: true` — 파일 바이트를 다 쓰면(2021+는 재질·스타일을 읽고 `model.dat`를 꺼낸 뒤 — 풀면서 읽으면 `model.dat`를 다 읽은 뒤, 2020 이하는 모형을 읽은 뒤)
  그 버퍼를 떼어 놓습니다(넘긴 `bytes`는 길이 0이 됨).
  파일 바이트를 더 쓰지 않는 쪽이 파일 크기만큼 덜 잡게 켭니다. 그림은 그 전에 `readSkpImages`로 꺼내야 합니다. 기본은 꺼짐.
- `skpFileToScene(file, opts)` — 파일(`Blob`·`File`, 또는 `{ size, read(start, end) }` 꼴의 `SkpSource` — `blobSource`·`bytesSource`)을 통째로 들지 않고 해석합니다.
  그림을 꺼내고(`readSkpImages`와 같음, 선택은 `images`) 그 무늬 그림으로 장면을 만들어 `{ scene, images, imageError }`를 냅니다. 결과는 파일 전체 바이트로
  `readSkpImages` → `skpToSceneAsync`(같은 선택, `textures`·`releaseBytes`)를 부른 것과 같습니다. 2021+ 꾸러미는 머리·끝 레코드·중앙 목록과 필요한 항목만 읽고
  압축된 `model.dat`는 1 MiB씩 읽으며 풉니다. 2020 이하·끝 목록이 없거나 깨진 꾸러미·SketchUp 파일이 아닌 것은 파일 전체를 읽습니다(`onFileRead`가 `parts`·`whole`로 알림).
  앱 워커와 훑기 도구가 이것을 씁니다. `sourceSha256(source)`은 같은 꼴의 파일을 덩이씩 읽어 파일 전체로 구한 것과 같은 SHA-256을 냅니다.
- `readModelDat`이 내는 중간 모형(`SkpModel`)의 면·모서리는 형식 배열 표(`SkpFaces`·`SkpEdges`)입니다. 고리는 두 단계 구간(면 → 고리 `loopStart`, 고리 → 꼭짓점 `cornerStart`)이고,
  없는 번호는 NaN입니다. 면 하나를 객체로 보려면 `faceAt`·`edgeAt`, 객체 목록에서 표를 만들려면 `facesFrom`·`edgesFrom`을 씁니다.
- 나무(`outline`)가 있으면 `meta.annotationRuns`에 주석 선분 묶음마다 선분 구간별 놓인 노드(`start`·`node`, -1 = 모형에 바로)를 적습니다.
- 치수·지시선 선분 묶음에는 선만 있고, 끝 표시와 연장선 넘침은 `meta.annotationMarks`(묶음 id → 표시마다 끝점·바깥 방향·치수 평면 수직 `geom`,
  꼴 `kind` 1 빗금·2 점·3 닫힌 화살·4 열린 화살·5 넘침, 붙은 선의 세계 길이 `span`, 놓인 노드 `node`)로 냅니다 — 화면 크기로 그릴 쪽(앱 `src/app/dimmarks.ts`)이 그립니다.
- 모형 스타일(또는 스타일을 쓰는 장면)의 모서리 색이 "재질별"·"축별"이면 `meta.style.edgeColorMode`(`'material'`·`'axis'` — 모두 같게는 없음)를 적고,
  모형 모서리 묶음(`skp-edges-*`·`skp-reveal-edges-*`)에 선분마다 정점 색(`LineSet3d.colors`)을 달며 그 방식을 `meta.edgeColoring`에 적습니다.
  묶음 색(`color`)은 그대로 스타일 모서리 색이라, 모두 같게인 장면에서는 그 색 한 색으로 덮으면 됩니다(앱은 코어 `setItemColor`).
- `textures: readSkpImages(bytes).materials` — 무늬 재질 면에 무늬 좌표(`Mesh3d.uvs`, 원근 무늬가 섞인 그물은 `(u·q, v·q, q)` 3값)와 무늬 id(`Mesh3d.texture`)를 두고,
  쓰인 그림을 `scene.textures`(`Texture3d`: 그림 바이트를 복사하지 않고 같은 배열, 화소 크기)에 넣습니다(코어 v0.5). `meta.textures`에는 무늬마다
  재질·폴더·그림 경로·무늬 크기(인치)·알파 가능성·색 바꾸기(`colorize`: 방식·재질 색·원래 평균색)를 적습니다. `maxTextures`·`maxUvVertices`로 한도를 바꿉니다.
  주지 않으면 예전처럼 평균색만 칠합니다(출력이 바뀌지 않음).

```ts
import { readSkpImages, skpToScene } from 'opencad-skp';

const images = readSkpImages(bytes);
const scene = skpToScene(bytes, { textures: images.materials }); // Viewer3d.setScene(scene)이 무늬를 풀어 입힌다
```

`meta`에는 판(`version`)·그릇(`container`)·단위(`lengthUnit`)·개수 통계와 함께, 태그별 면·모서리 수(`tagStats`), 재질별 색·면 수·그물 id·꾸러미 폴더·입힌 무늬 id(`materialStats`),
깨짐·한도 표시(`damaged`·`limited`)가 들어 있습니다. 2026-10에 더한 칸(`units`·`camera`·`pages`·`activePage`·`style`·`tagFolders`·`modelName`·`texts`·`dimensions`·`sectionPlanes`·
`annotationItems`·`attributes`·`treeInfo` 등)의 꼴은 [`src/meta.ts`](src/meta.ts)에 있습니다. 파일 스타일에 앞면 색이 있으면 재질 없는 면을 그 색으로 칠합니다.

꾸러미 안 그림은 `readSkpImages(bytes, { maxCount, maxBytesEach, maxTotalBytes })`로 꺼냅니다: 모형 미리보기(`meta/model_thumbnail.png`), 재질 폴더별 무늬 그림,
컴포넌트 미리보기(`thumbnails/`), 장면 미리보기(`scene_thumbnails/`). 꼴은 첫 바이트로 가리고 개수 600·한 장 8 MB·전체 64 MB 한도를 둡니다.
재질 폴더에 그림이 여럿이면(PBR 그림 등) material.xml이 가리키는 그림을 고릅니다. 색 바꾸기 규칙은 `colorizeRgba(rgba, { type, color, average })`로 씁니다.
2020 이하 파일은 객체 직렬화 안의 그림 기록(`CDib`: 모형 미리보기·재질 무늬·컴포넌트 미리보기·2020 장면 미리보기)을 꺼냅니다. 같은 바이트로 `skpToScene`을 먼저 불렀으면 그때 모은 자리를 써서 다시 풀지 않습니다.

## 개발

```bash
npm install
npm run dev        # http://localhost:4403/ (예제 바로 열기: http://localhost:4403/?sample)
npm run typecheck
npm test
npm run build      # dist/
npm run preview
```

시험은 표본 파일 없이 `tests/build.ts`(본체는 `src/app/skpwrite.ts`)와 `tests/mfcwrite.ts`(2020 이하 꼴)로 만든 작은 바이트로 돌립니다. 표본 파일은 저장소에 넣지 않습니다.
확인용 표본·임시 파일은 `.runtime/`(git 무시)에만 둡니다.
`SKP_BIG=1 npx vitest run tests/large.test.ts`는 수십만 면 합성 모형으로 해석 시간을 재고 `.runtime/tmp/`에 파일을 씁니다(확인 뒤 지우세요).
3D 뷰어 코어는 v0.20.0(단면 보기·묶음 원점·무늬, 터치 끌기 문턱 10화소·터치 고르기 허용 14화소, 0.7.0의 여러 단면·잘린 면 묶음 채우기·숨은 선·단색·해 조명·그림자·안개·하늘 바탕·걷기·마주 보는 그물·뒷면 재질·렌즈 이동, 0.7.1의 삼각형 변 끄기 `triangleEdges`·선분 묶음 뒤 모서리 점선 `hiddenEdges`, 0.8.0의 음영 방식 뒤 모서리 점선·선 색 선택 `edgeColor`·외곽선 색·걷기 중력과 부딪힘, 0.9.0의 교차점 계산 `segmentIntersection`·캔버스 키보드 초점 테두리·큰 배열 나눠 올리기, 0.9.1의 누른 뒤 초점 테두리 감추기, 0.10.0의 작은 `camera` 모듈의 표준 뷰 키 표 `VIEW_KEYS`·잠근 선 위 점 `lockedSnap`, 0.12.0의 모서리 끝 방향 잠금 판정 `edgeLineLock`, 0.13.0의 측정 글 자리 고르기 `placeMeasureLabel`, 0.20.0의 그물 면만 고르기 `pick(x, y, { meshesOnly: true })`)으로 받습니다.
0.9.0부터 코어가 캔버스의 키보드 초점 테두리(`:focus-visible`일 때만 안쪽 2화소)를 그리므로, 앱은 그 색만 강조색으로 둡니다(`--v3d-focus`).
0.9.1부터는 키보드로 초점을 준 캔버스를 마우스·터치로 누르면 테두리가 사라지고, Tab으로 다시 오면 보입니다(앱의 전역 `:focus-visible` 규칙보다 코어 규칙이 구체적). 줄자·각도기는 코어 측정을 쓰지 않고 앱 추정(`snap.ts`)이 축을 정하므로 0.9.1의 `MeasureResult.axisA`·`axisB`는 쓰지 않습니다.
0.10.0의 추론 잠금·나란함(`setMeasureSnap({ inference: { lock, parallel } })`, `setMeasureInferenceLock`)도 코어 측정 모드 안의 상태라 쓰지 않고,
같은 규칙(누르는 순간의 방향 추론 잠금, 점 추정은 잠근 선에 수직으로 내림, 두 점째에서 풀림, 지나간 모서리와 나란함)을 앱 추정에 넣었습니다.
앱 추정은 축을 화면 각 6°로 고르고 모형의 그리기 축을 따르며, 나란함도 같은 각으로 고릅니다(코어는 화면 붙잡기 거리와 세계 축).
잠근 선 위 점은 코어 순수 함수 `lockedSnap`(`opencad-viewer3d/inference` — 측정 도구 조각과 함께 받는 작은 모듈)을 그대로 씁니다.
0.11.0~0.14.0에는 이 앱이 따로 만든 것이 코어로 들어갔고, 그 가운데 코어 순수 함수로 바꿀 수 있는 것은 바꿨습니다(15차).
모서리 끝에서 그 모서리를 따라 가리킬 때의 방향 잠금 판정(직선이 시작점을 지나는지, 커서 점이 시작점 자리인지)은 0.12.0 `edgeLineLock`에 모서리마다 맡깁니다.
허용치는 앱이 쓰던 상대 1e-6(모서리 길이·시작점 거리에 견줌)을 넘기고, 코어는 세계 축만 알아 축은 모형의 그리기 축으로 앱이 고릅니다.
시험이 바꾸기 전 판정과 합성 4,000가지(세계·옮긴 그리기 축, float32 좌표, 큰 좌표, 허용치 둘레의 비낀 시작점)를 견줘 모두 같고,
다른 것은 커서 점이 시작점에서 상대 1e-9~1e-6 안일 때(같은 꼭짓점으로 보고 잠그지 않음)뿐입니다.
결과 글이 가린 자리를 비키는 차례는 0.13.0 `placeMeasureLabel`(`opencad-viewer3d/measurelabel`)을 씁니다.
줄자·각도기는 코어 측정 모드를 쓰지 않으므로, 그 안의 상태인 `setMeasureInferenceLock({ direction, edge, kind })`·`measureHoverLock`·`measurePoints`·`measureLabelRect`·`setMeasureLabelAvoid`는
쓰지 않고 같은 규칙만 따릅니다(측정 글이 비킬 자리는 앱이 아는 측정 띠·측정값 칸·정밀 조준 십자선·손가락·툴팁).
0.14.0의 붙잡기 점 다듬기(`setMeasureSnap({ refine })`)는 쓰지 않습니다. SketchUp 모형은 호·원도 모형이 가진 모서리 선분 그대로라 화면에 그리는 꺾은선이 곧 형상이고,
끝점·중간점·모서리 위 점·시작점에서 내린 수직 발이 이미 정확한 값입니다(호·원의 중심은 해석기의 곡선 정보로 앱이 따로 구함).
0.15.0의 멀리서 내린 곡선 위 수직 발과 두 곡선의 교차점 다듬기도 `refine`을 줄 때만 붙으므로 이 앱에는 바뀌는 것이 없습니다(16차에 올림 —
같은 헤드리스 측정 순서 15단계의 값·추정·잠금·결과 글 자리·3D 보기 그림이 0.14.0 빌드와 모두 같음).
0.16.0의 붙잡은 선분 식별자(`measurePoints[].segment`)와 끌어온 축(`setMeasureSnap({ inference: { track } })`)도 코어 측정 모드 안의 것이라 올리기만으로는 바뀌는 것이 없습니다
(17차에 올림 — 같은 헤드리스 측정 순서 15단계의 값·추정·잠금·결과 글 자리·3D 보기 그림이 0.15.0 빌드와 모두 같음).
끌어온 축은 같은 규칙의 순수 함수(`opencad-viewer3d/track`의 `MeasureTracker`·`trackCrossSnap`·`trackAxisSnap`)로 줄자·각도기에 넣었습니다(17차).
0.17.0의 끌어온 축끼리의 교차(`trackPairSnap`)와 끌어온 축과 모서리의 교차(`trackEdgeSnap`)는 코어 README "앱이 할 일"대로 시작점 축 위 줄 맞춘 자리와
`chooseTrackPoint`로 묶어(화면에서 가까운 것, 뒤 차례는 1화소 넘게 가까워야 이김) 시작점 축 앞에 두고, 모서리는 커서 둘레에서 고른 선분에 그 깊이 한 화소의 세계 길이(`wpp`)를 붙여 줍니다(18차).
앱 추정(`snap.ts`)의 차례는 점 추정 → 끌어온 점 후보와 축이 모서리·면과 만나는 점 가운데 점인 것(줄 맞춘 자리·축끼리 교차·끌어온 축과 모서리·시작점 축과 모서리·
축이 면을 뚫는 점) → 모서리 위 → 축·나란함·수직 → 끌어온 축이고, 축은 모형의 그리기 축(`axes`)을 넘깁니다.
0.17.0으로 올리기만 한 빌드는 같은 헤드리스 측정 순서 15단계의 값·추정·잠금·결과 글 자리·3D 보기 그림이 0.16.0 빌드와 모두 같았습니다.
0.18.0의 시작점 축과 모서리의 교차(`axisEdgeSnap`)와 축이 면을 뚫는 점(`axisFaceSnap`)은 코어 README "앱이 할 일"대로 `chooseTrackPoint` 묶음 끝에
모서리 → 면 차례로 넣었습니다(19차). 모서리는 끌어온 축과 같은 커서 둘레 선분을 주고, 면은 커서 고르기가 그물 면(단면 채운 면이 아님)일 때 그 삼각형 꼭짓점으로 평면을 정해
`under`로, 그 자리의 그물 면만 고르기(0.20.0 `viewer.pick(x, y, { meshesOnly: true })` — 숨긴 항목·단면에서 잘린 쪽을 거름)를 `hitAt`으로 줍니다
(20차까지는 선을 면보다 앞세우는 보통 고르기를 주고, 그 자리에서 선이 맞으면 그 선이 앞서 맞춘 면 평면 위(1.5화소 안)이고 광선이 그 삼각형 안일 때만 그 면으로 봤습니다).
축 직선은 시작점 X·Y·Z와 끌어온 점 X·Y·Z(앞 직선과 같은 직선은 뺌)를 하나씩 넘기고, 다시 맞춰 보는 고르기는 한 번 추정에 12번까지입니다.
`MeasureTool`의 `axisMeets: false`·`setAxisMeets(false)`로 끌 수 있고, 끄면 같은 헤드리스 측정 순서 15단계의 값·추정·잠금·결과 글 자리와
그림을 찍는 때의 측정 덧그림 DOM이 18차 빌드와 같습니다. 3D 보기 그림은 18차 빌드와 두 번 견주어 두 번 다 같은 4화소가 1만큼 달랐는데,
20차에 19차 빌드를 설정을 건드리지 않고 두 번 돌려 보니 둘째 번 각도기 그림이 그 4화소만 1만큼 달라 19차의 끈 그림과 화소까지 같았습니다.
끄기 때문이 아니라 같은 빌드를 다시 돌릴 때 생기는 그리기 흔들림입니다(그 자리에서 두 그림 가운데 하나가 나옴).
켠 채로도 그 15단계(시작점이 없는 단계 포함)는 값이 모두 같았습니다(그 순서에는 축이 모서리·면과 만나는 자리가 없음).
0.18.0으로 올리기만 한 빌드도 같은 15단계의 값과 3D 보기 그림까지 0.17.0 빌드와 모두 같았습니다.
0.19.0의 잠근 선과 선분의 교차(`lockEdgeSnap`)와 잠근 선이 면을 뚫는 점(`lockFaceSnap`)은 코어 README "앱이 할 일"대로 잠근 동안 커서 밑 점 추정(잠근 선에 내린 자리)과
잠근 선 위 커서에 가까운 점 사이에 넣었습니다(20차). 둘 사이는 `chooseTrackPoint`(모서리가 앞)이고, 선분·면 맞춤은 19차 시작점 축과 같은 것을 넘기며 잠근 방향을 `dir`로 줍니다.
면이 모형 그대로 평면이라 0.19.0의 곡면 다듬기(`refineFace`)는 쓸 곳이 없습니다. `MeasureTool`의 `lockMeets: false`·`setLockMeets(false)`로 끌 수 있고,
끄거나 켠 빌드 모두 같은 헤드리스 측정 순서의 값·추정·잠금·결과 글 자리·덧그림 DOM이 19차 빌드와 같았으며(켠 빌드는 그 순서의 잠근 자리에 만나는 점이 없음),
각도기 3D 보기 그림은 위의 두 그림 가운데 하나였습니다. 0.19.0으로 올리기만 한 빌드는 3D 보기 그림까지 19차 빌드와 같았습니다.
0.20.0으로 올리며(21차) 축·잠근 선이 면을 뚫는 점을 다시 맞춰 보는 고르기를 코어 README "앱이 할 일"대로 그물 면만 고르기로 바꾸고, 앱이 따로 하던 면 위 선 판정을 없앴습니다.
면 위에 그린 선은 예전과 같이 면을 가리지 않고, 면 앞에 떠 있는 선이 그 자리 6화소 안을 지나도 이제는 그 밑 면에 붙습니다(선은 그 자리 화소를 덮지 않음).
같은 헤드리스 측정 순서(줄자·각도기 17단계와 3D 보기 그림, 넓은 화면·375px의 잠근 축이 면·모서리와 만나는 자리)의 값·추정·잠금·결과 글 자리·덧그림 DOM이 20차 빌드와 모두 같았고,
예제 모형의 시작점 16곳에서 세 축을 따라(잠그지 않고·그 축에 잠그고) 3만 8천여 자리의 추정을 견줘도 모두 같았습니다.
그 가운데 다시 맞춰 보는 고르기는 두 판 다 260번이었고(20차 판정에서 선이 맞은 10번도 새 고르기로 같은 면), 그 고르기에 든 시간은 모두 합쳐 5 ms에서 3 ms였습니다.
0.20.0의 축과 꺾은선 토막의 열린 교차(`openEdgeSnap`)와 축이 아닌 잠근 선 다듬기는 `refine`을 줄 때만이고, SketchUp 곡선은 모형 선분 그대로라 쓰지 않습니다.
0.20.0으로 올리기만 한 빌드도 같은 측정 순서와 위의 추정이 20차 빌드와 모두 같았습니다.
머무르기 시간은 코어 `TRACK_DWELL_MS`(0.5초)로 앱이 재고(`setTimeout`), 정밀 조준만 손가락 떨림을 받으려고 머물기 시작한 자리 6화소 안을 같은 자리로 봅니다.
기본으로 켜 두되(SketchUp에는 끄는 설정이 없고, 0.5초 동안 2화소 안에 멈춘 커서만 세어 지나가는 커서는 끌어오지 않음) `MeasureTool`의 `track: false`·`setTrack(false)`로 끌 수 있고,
끄면 상태가 없어 같은 헤드리스 측정 순서의 값·추정·잠금·결과 글 자리가 끄기 전 빌드와 같습니다(3D 보기 그림은 같은 빌드끼리도 몇 화소가 1만큼 흔들리는 범위 안).
0.11.0의 그물 하나 바꾸기(`setMesh`·`removeMesh`)도 쓸 곳이 없습니다(보이기는 `setItemVisible`·`setGroupVisible`, 새 문서는 장면 전체).
새 API를 쓰지 않으면 코어는 0.10.0과 화소·값까지 같다고 코어 판마다 화소 비교로 밝혀 두었고, 이 앱도 헤드리스로 같은 측정 순서(끝점에서 모서리를 따라 Shift 잠금,
축 추정, 각도기)를 0.10.0 빌드와 견줘 값·추정·잠금·결과 글 자리와 3D 보기 그림이 모두 같은 것을 확인했습니다.
숨은 선 방식의 뒤 모서리 점선이 보이는 모서리 끝에 조금 겹치던 것과, 새로 올릴 배열이 8 MB를 넘는 묶음을 4 MB씩 여러 프레임에 나눠 올리는 것은 코어가 바꾼 기본 동작입니다.
0.7.0에서 쓰던 길이 0 윤곽선을 달아 늘 숨기는 꼼수(`addEdgeStubs`)는 0.7.1로 올리며 없앴습니다.
측정 도구의 누르기 문턱은 코어의 `dragStartPx`(마우스·펜 4, 터치 10화소)를, 추정의 가운데·둘레 고르기는 코어 마우스 허용 거리(6화소)를 그대로 씁니다(터치 추정 반경 22화소가 코어 터치 허용 거리 14화소를 덮습니다).

**첫 화면 JS**: 시작 화면(파일 열기·최근 문서·예제·언어 메뉴)은 코어와 측정 도구 없이 그립니다. 코어 입구(`opencad-viewer3d` — 뷰어·렌더러·셰이더·고르기)와
측정 도구(`measure.ts`·`snap.ts`와 코어 `inference` — 줄자·각도기·추정·안내 두기·고르기)는 파일을 열기 시작할 때 `src/app/core.ts`의 `import()`로 워커 해석과 함께 받습니다
(오프라인 앱은 서비스 워커가 이 조각들도 미리 담음). 뷰어는 측정 도구를 기다리지 않고, 측정 도구는 받는 대로 만듭니다.
그 전에 줄자·각도기를 누르면 `FirstUse`가 받은 뒤 마지막으로 누른 도구를 켜고(받기는 한 번, 다시 누르거나 Esc면 거둠), 받지 못하면 연결이 끊겼는지에 따라 쉬운 안내를 보입니다.
받지 못한 조각은 다음에 부를 때 다시 받습니다(`onceImport`).
첫 화면 모듈은 작은 코어 모듈(`camera`·`pointer`·`viewcube`·`theme`·`section`·`types`·`math`·`bounds`)만 값으로 가져오고,
표준 뷰 키 표(`keys.ts`)와 단면 수 한도(`doc.ts`)는 같은 값을 앱에 두어 시험이 코어 표와 견줍니다. 측정 도구를 받기 전에 쓰는 키 규칙(안내 두기 키)은 `measurehints.ts`에 두고,
도구를 켠 뒤에만 쓰는 잠금·안내 두기 키 안내 글과 잠근 방향 이름은 측정 도구 조각이 줍니다(`lockHintText`·`lockName`).
`tests/app/core-split.test.ts`가 `src/app/main.ts`에서 정적 가져오기로 닿는 모듈만 따라가 이 규칙을 지킵니다(인라인 `type`만 쓴 가져오기도 `verbatimModuleSyntax`에서는 모듈을 불러오므로 값으로 셉니다).
2026-10-29 기준(코어 v0.20.0) 첫 화면 JS는 270 KB(gzip 93.9 KB — 측정 도구를 나누기 전에는 313 KB · 107 KB, 코어를 나누기 전에는 467 KB · 158 KB)이고,
문서를 열 때 받는 코어 조각은 207 KB(gzip 68 KB — v0.10.0은 187 KB · 61 KB), 측정 도구 조각은 61 KB(gzip 20 KB)와
코어 `inference`·`snap`·`measurelabel`·`track`을 묶은 조각 22 KB(gzip 8 KB), 해석 워커 조각은 204 KB(gzip 77 KB)입니다. v0.14.0으로 올리며 첫 화면에 남는 `bounds` 모듈이 조금 커져(gzip 15바이트),
잠금 안내 글을 측정 도구 조각으로 옮겨 첫 화면은 오히려 0.4 KB(gzip) 줄었습니다. v0.15.0은 첫 화면을 바꾸지 않고 코어 조각(gzip +0.7 KB)과 `inference` 조각(+0.6 KB)만 키웁니다.
v0.16.0도 첫 화면을 바꾸지 않고, 뷰어 측정 모드에 들어온 끌어온 축으로 코어 조각만 gzip 1.6 KB 커집니다.
줄자·각도기의 끌어온 축(17차)은 `track` 모듈을 측정 도구와 나눠 받는 조각으로 옮겨 코어 조각 −0.7 KB, 나눠 받는 조각 +0.7 KB, 측정 도구 조각 +1.0 KB(gzip)이고 첫 화면은 그대로입니다.
v0.17.0과 끌어온 축끼리·모서리와의 교차, 휴대폰 다시 재기(18차)도 첫 화면을 늘리지 않고(조각 이름의 해시를 같은 글로 바꾸고 gzip하면 전·후 같음 — 다시 재기 단추를 켤지는 측정 도구 조각이 정함),
코어 조각 +0.4 KB, 나눠 받는 조각 +0.8 KB(코어 `track`), 측정 도구 조각 +0.5 KB(gzip)입니다.
v0.18.0과 축이 모서리·면과 만나는 점(19차)도 첫 화면을 늘리지 않고(조각 이름의 해시를 같은 글로 바꾸고 gzip하면 전·후 같음),
코어 조각 +1.0 KB(뷰어 측정 모드에 들어온 같은 후보), 나눠 받는 조각 +0.5 KB(코어 `track`), 측정 도구 조각 +0.9 KB(gzip)입니다.
v0.19.0과 잠근 선이 모서리·면과 만나는 점(20차)도 첫 화면을 늘리지 않고(같은 방법으로 전·후 같음),
코어 조각 +0.4 KB(뷰어 측정 모드에 들어온 같은 후보), 나눠 받는 조각 +0.1 KB(코어 `track`), 측정 도구 조각 +0.3 KB(gzip)입니다.
v0.20.0과 면만 다시 맞추기(21차)도 첫 화면을 늘리지 않습니다(같은 방법으로 전·후 같음). 코어 `track`이 코어 `snap`을 가져오게 되어 `snap`이 코어 조각에서
나눠 받는 조각으로 옮겨 가(둘 다 문서를 열 때 받음) 코어 조각 −1.1 KB, 나눠 받는 조각 +2.5 KB이고, 측정 도구 조각은 면 위 선 판정을 빼 −0.2 KB(gzip)입니다.
결과 글이 뷰 큐브·장면 탭·가장자리를 비키기와 한 손 잠금(잠글 방향 고르기 줄 — 22차)은 측정 도구 조각에 두어(`mountLockMenu`·`toggleLockMenu`)
첫 화면은 쓰지 않게 된 "잠글 방향이 없습니다" 알림 글만큼 줄었고(gzip 93,886 → 93,831바이트) 측정 도구 조각은 +0.8 KB(gzip)입니다.
파일을 통째로 들지 않고 열기(16차)는 첫 화면에서 지문 계산을 빼 gzip 12바이트 줄였고, 해석 워커 조각은 조각 읽기와 SHA-256으로 gzip 3.3 KB 늘었습니다.
안내 되돌리기·다시 하기·안내 보이기·파일별 안내 기억처럼 측정 도구에 딸린 기능은 단추·메뉴 항목·키 처리·저장까지 측정 도구 조각에 두고
(`mountUndo`·`guideMenuItems`·`undoKey`·`openFile`·`guidestore.ts`), 첫 화면에는 부르는 줄만 둡니다(파일 내용 지문은 해석 워커가 구해 보냄).
휴대폰 검사 워크플로는 Lighthouse 전·후 가운데값을 `tools/performance-budget.json`(성능 90 이상, FCP 2.2초·LCP 2.5초·TBT 400 ms 아래, JS 108 KiB 아래 등)과
견주어(`opencad-site check-performance-budget`) 넘으면 실패합니다. 코어를 다시 첫 화면에 넣으면 JS가 약 57 KiB 늘어 이 단계에 걸리고, 측정 도구는 약 15 KiB 늘립니다.

### 실제 파일 훑기

해석기를 고치기 전과 뒤에 가진 SketchUp 파일을 모두 열어 보고 결과를 견주는 도구입니다(`scripts/sweep/`). 표본은 저장소에 없으므로 각자 로컬 폴더를 줍니다.

```bash
npm run sweep -- --dirs "$HOME/Documents:$HOME/Downloads" --out .runtime/sweep/before   # 폴더는 쌍점으로 구분(OPENCAD_SWEEP_DIRS도 됨)
npm run sweep -- --dirs "$HOME/Documents:$HOME/Downloads" --out .runtime/sweep/after
npm run sweep:compare -- .runtime/sweep/before .runtime/sweep/after --fail-on-change
npm run sweep -- --dirs "$HOME/Downloads" --min-mb 25 --mem --jobs 1 --out .runtime/sweep/mem   # 큰 모형의 단계별 메모리
```

- 폴더 아래를 모두 훑어 `.skp`를 고르고(`node_modules`, `.git`, `.claude` 폴더는 건너뜀) 내용이 같은 파일은 sha256으로 한 번만 엽니다. 해석은 앱 워커와 같은 `skpFileToScene`·같은 선택으로 합니다. 파일은 Node 파일 손잡이로 필요한 자리만 읽고(2020 이하 등은 통째로), 압축된 `model.dat`가 1 MiB 넘는 2021+ 파일은 내장 풀기로 풀면서 읽습니다.
  `--stream-min 0`을 주면 압축된 모든 2021+ 파일이 그 길을 탑니다(풀면서 읽기를 고친 뒤 모든 파일로 견줄 때). 요약에 `model.dat`를 어떻게 읽었는지(`modelRead`)와
  파일을 어떻게 읽었는지(`fileRead` — 필요한 자리만·통째로)별 파일 수를 적습니다.
- 해석은 Node 자식 프로세스 여러 개(`--jobs`, 기본은 CPU 절반이고 많아야 4)가 나눠 합니다. 파일 하나가 `--timeout`(기본 300초)을 넘거나 프로세스가 죽으면 그 파일을 예외로 적고 이어 갑니다.
- 결과 폴더에는 파일마다 한 줄씩 적은 `records.jsonl`(열쇠는 내용 해시)과 요약 `summary.json`을 씁니다. 요약에는 판마다 정상, 경고, 빈 장면, 읽지 않는 판, SketchUp 파일 아님, 예외로 나눈 개수와 경고 종류별 파일 수, 면과 정의와 인스턴스 합, 해석 시간 백분위, 큰 파일의 시간과 메모리가 들어갑니다. 파일 경로는 `records.jsonl`에만 있으니 결과는 `.runtime/`(git이 무시함)에 두고 저장소에 넣지 않습니다.
- 파일마다 장면 출력 해시(`digest` — 모든 그물·선분·점 배열의 바이트, 무늬, 경고, meta)를 적습니다. 해석기 자료 구조를 바꿀 때 좌표 하나가 바뀐 것까지 찾으려고 넣었습니다.
- `sweep:compare`는 같은 해시끼리 견주어 분류가 바뀐 파일, 지표나 경고나 장면 출력 해시가 바뀐 파일(`--top` 개수만큼), 새 예외를 찍습니다(장면 출력 해시는 두 결과에 다 있을 때만 봅니다). `--fail-on-change`를 주면 바뀐 것이 있을 때 1로 끝납니다.
- `--mem`은 파일마다 새 프로세스를 띄워 단계(그림 꺼내기, 꾸러미, 해석 — 풀면서 읽으면 풀기도 여기, 장면 만들기)마다 가장 컸던 heap, external, rss, 같은 때의 heap + external 합과 그 파일을 여는 동안의 최대 rss를 잽니다. 기계의 메모리가 빠듯하면 rss가 같은 코드에서도 수백 MB씩 흔들리므로 heap + external로 견줍니다. 단계마다 gc를 부르므로 이때 잰 시간은 다른 결과와 견주지 않습니다.
- 폴더를 주지 않으면 쓰는 법만 찍고 끝나므로 CI에서는 돌지 않습니다.

## 검색·공유 메타데이터와 콘텐츠 수정일

`site/metadata.json`을 공통 원본으로 삼아 Vite 플러그인이 제목·설명·canonical·Open Graph·Twitter Card·JSON-LD를 초기 HTML에 넣습니다. 같은 원본으로 앱의 공개 주소를 담은 `sitemap.xml`도 생성합니다. 공유 이미지는 각 앱의 `public/og-opencad.jpg`이며 앱 파일과 함께 배포합니다. `robots.txt`는 같은 호스트 루트(`https://gyutae-kim.github.io/robots.txt`)의 설정이 적용됩니다.

`site/content-history.json`에는 실제 콘텐츠 수정 시각과 지문을 저장합니다. 초기 HTML 본문·메타데이터·공유 이미지와 빌드된 앱/워커 JavaScript·CSS를 비교하므로 앱 기능이 바뀌면 날짜 갱신이 필요합니다. 수정일 자체와 소스 맵은 비교에서 제외합니다.

1. 콘텐츠를 변경한 실제 UTC 시각을 기록하고 `npm run update:content-dates -- --at YYYY-MM-DDTHH:mm:ssZ`를 실행합니다.
2. `npm run build`로 다시 빌드합니다. 변경되지 않은 콘텐츠는 기존 날짜를 유지하며, 날짜가 오래되었거나 잘못된 경우 SEO 검사가 실패해 배포를 막습니다.
3. `npm run test:seo`와 기존 테스트를 실행하고 메타데이터·수정일 기록을 함께 커밋합니다.

일반 빌드나 배포 시각으로 날짜를 자동 갱신하지 않습니다. `sitemap.xml`의 `lastmod`와 앱 구조화 데이터의 `dateModified`는 동일한 기록을 사용합니다. 배포 뒤에는 앱·사이트맵·공유 이미지의 실제 공개 응답을 확인하고, 포트폴리오 통합 사이트맵의 연결 날짜도 새 앱 사이트맵과 맞춥니다. 사이트맵 게시와 검색엔진의 실제 수집·색인 완료는 별도로 확인합니다.


## 다국어 UI와 정적 소개

한국어 기본 주소와 영어(`/en/`), 일본어(`/ja/`), 중국어 간체(`/zh-CN/`), 독일어(`/de/`) 페이지를 제공합니다. 각 언어의 소개 본문과 검색·공유 메타데이터를 빌드할 때 생성하며, `hreflang`과 사이트맵이 같은 페이지의 언어들을 연결합니다. `site/locales/*.json`에 한국어 원문과 번역을 저장하고, 브라우저는 선택한 언어의 사전만 내려받습니다. 방문 중 외부 번역 서비스는 호출하지 않습니다.

우측 상단 지구본 아이콘에서 언어를 선택합니다. 방향키로 이동하고 Escape나 바깥 클릭으로 닫을 수 있습니다. 언어 선택은 URL에 반영하며, 열린 문서나 편집 상태를 다시 만들지 않고 화면 문구·접근성 설명·오류·도움말을 갱신합니다. 명령 식별자·입력값·파일명·모델 이름·원본 도면의 문자는 번역하지 않습니다. 새 데이터 이름을 표시하는 요소에는 `translate="no"`를 지정하고, UI 문구의 `{0}` 같은 변수 자리를 변경하지 마세요. 여러 줄 메시지와 새 한국어 문구도 번역 사전에 추가해야 합니다. ` · `로 이은 문장은 짧은 변수 문구(예: `면 {0}`)가 뒤 조각까지 그대로 잡으면 조각마다 따로 옮깁니다(남는 한국어가 적은 쪽을 고름 — 잡은 이름은 여전히 그대로).

`npm run test:i18n`은 언어 전환과 문서 데이터 보존을, `npm run check:i18n`은 다섯 언어의 정적 소개·canonical·언어 링크·사전 변수·에셋 경로를 검사합니다. 번역이나 앱을 수정하면 기존 콘텐츠 수정일 갱신 절차를 따른 뒤 다시 빌드합니다. 자동 번역 초안의 주요 메뉴와 제품명은 교정했으며, 긴 기술 설명에는 추가 원어민 감수가 필요합니다.
